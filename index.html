1Overview

lib/database.js is the foundation of the bot's database layer. It creates a single, reusable Sequelize connection — SQLite locally, Postgres in production.

🗄️
Dual Database Support SQLite for local dev, Postgres for cloud
🔒
Singleton Pattern One connection, zero memory leaks
⚙️
Env-Based Config Switch via DATABASE_URL
🌐
SSL Support Works with Neon, Supabase, Railway
🔄
Auto-Sync Tables created automatically
🧹
Silent Logging Clean console output

4Configuration

All configuration lives in a single environment variable: DATABASE_URL.

ℹ️ How it works

If DATABASE_URL is not set → SQLite (./database.db).

If it is set to a Postgres URL → Postgres with SSL.

SQLite (development)

DATABASE_URL=./database.db

Postgres — Neon

DATABASE_URL=postgres://user:password@ep-xxx.neon.tech/neondb?sslmode=require

Postgres — Supabase

DATABASE_URL=postgres://postgres:password@db.xxx.supabase.co:5432/postgres

Postgres — Railway

DATABASE_URL=postgresql://postgres:password@containers-us-west-xxx.railway.app:5432/railway

Postgres — Local

DATABASE_URL=postgres://postgres:password@localhost:5432/mydb

5Line-by-Line Explained

Every line of the source, explained in Sinhala.

Full source code

const Sequelize = require('sequelize');

class DatabaseManager {
    static instance = null;

    static getInstance() {
        if (!DatabaseManager.instance) {
            const DATABASE_URL = process.env.DATABASE_URL || './database.db';

            DatabaseManager.instance =
                DATABASE_URL === './database.db'
                    ? new Sequelize({
                            dialect: 'sqlite',
                            storage: DATABASE_URL,
                            logging: false,
                      })
                    : new Sequelize(DATABASE_URL, {
                            dialect: 'postgres',
                            ssl: true,
                            protocol: 'postgres',
                            dialectOptions: {
                                native: true,
                                ssl: { require: true, rejectUnauthorized: false },
                            },
                            logging: false,
                      });
        }
        return DatabaseManager.instance;
    }
}

const DATABASE = DatabaseManager.getInstance();

DATABASE.sync()
    .then(() => {
        console.log('Database synchronized successfully.');
    })
    .catch((error) => {
        console.error('Error synchronizing the database:', error);
    });

module.exports = { DATABASE };

① Import Sequelize

const Sequelize = require('sequelize');

sequelize npm package එක load කරනවා. Sequelize = Node.js ORM එකක් — SQL ලියන්නේ නැතුව JavaScript වලින් database එක handle කරන්න පුළුවන්.

③ Get instance method — the heart ❤️

static getInstance() {
    if (!DatabaseManager.instance) {
        // ... create connection
    }
    return DatabaseManager.instance;
}
✅ Why this matters

Call 1: null → CREATE connection

Call 2, 3, 4…: returns the same connection

Result: zero leaks, single DB handle.

⚠️ About rejectUnauthorized: false

Neon, Supabase, Railway වගේ cloud DB providers self-signed SSL certificates පාවිච්චි කරනවා. Node.js default reject කරනවා — ඒ නිසා මේක අවශ්‍යයි.

⑦ Sync database

DATABASE.sync()
    .then(() => {
        console.log('Database synchronized successfully.');
    })
    .catch((error) => {
        console.error('Error synchronizing the database:', error);
    });
🚨 Known issue

sync() is not awaited. If queries run before sync finishes → "Table not found" errors.

Fix: call await DATABASE.sync() in your bot's startup.

⑧ Export

module.exports = { DATABASE };

Import කරන විදිය (destructuring):

const { DATABASE } = require('./lib/database');

6How It Works

The full execution flow when the bot starts.

Step 1: node index.js
    ↓
Step 2: index.js → require('./lib/database')
    ↓
Step 3: database.js executes
    ├── import Sequelize
    ├── define DatabaseManager class
    ├── call getInstance()
    │   ├── instance = null → CREATE
    │   ├── read DATABASE_URL
    │   │   ├── missing → SQLite
    │   │   └── present → Postgres
    │   └── new Sequelize(...)
    ├── DATABASE = instance
    ├── DATABASE.sync() [async]
    └── module.exports = { DATABASE }
    ↓
Step 4: index.js → require('./store')
    ↓
Step 5: store.js → require('./lib/database')
    └── cached → same instance ✅
    ↓
Step 6: Bot ready ✅

7API Reference

What you can do with the exported DATABASE object.

MethodPurpose

DATABASE.sync()Create/update tables
DATABASE.sync({ alter: true })Update schema (dev)

8Usage Examples

Real-world patterns you'll use every day.

1. Define a model

const { DATABASE } = require('../lib/database');
const { DataTypes } = require('sequelize');

const Contact = DATABASE.define('Contact', {
    jid:  { type: DataTypes.STRING, primaryKey: true },
    name: { type: DataTypes.STRING, allowNull: true },
});

module.exports = Contact;

2. Save / load data

// Save
await Contact.upsert({ jid, name });

// Load
const contact = await Contact.findOne({ where: { jid } });
const name = contact ? contact.name : jid.split('@')[0];

3. Transaction

return await DATABASE.transaction(async (t) => {
    await Message.create({ jid: from, ...msg }, { transaction: t });
    await Message.create({ jid: to,   ...msg }, { transaction: t });
});

4. Startup with proper sync

async function startBot() {
    const { DATABASE } = require('./lib/database');
    await DATABASE.sync();
    console.log('DB ready ✅');
    await startWhatsApp();
}

startBot().catch(console.error);

10Troubleshooting

Common errors and their fixes.

Please install sqlite3 package manually

npm install sqlite3

Cannot find module 'pg'

npm install pg pg-hstore

Table doesn't exist

Cause: sync() was not awaited.

await DATABASE.sync();
// then run your queries

SQLITE_BUSY: database is locked

Cause: Multiple connections or concurrent writes. Use the singleton (this file) or migrate to Postgres.

Self signed certificate error

Fix: Ensure ssl: { require: true, rejectUnauthorized: false } in dialectOptions.

11FAQ

Can I use MySQL instead?

Yes — change dialect: 'postgres' to 'mysql' and install mysql2. The rest of the file works unchanged.

Why use a singleton?

Without it, each require() would create a new DB connection. With 10 files importing this, you'd have 10 connections — memory leak + SQLite lock errors. The singleton guarantees one shared instance.

Should I commit database.db to git?

No. Add it to .gitignore — databases contain user data and should never be in version control.

Does this work with Netlify?

This particular file is a Node.js module and does not run on Netlify's static hosting — it runs on your bot's server. But this documentation site itself is fully Netlify-ready (see next section).

12Deploy to Netlify

Ship this documentation site in under a minute.

Option A — Drag & drop

  1. Save this file as index.html in a folder.
  2. Go to app.netlify.com/drop.
  3. Drag the folder into the drop zone.
  4. Netlify generates a live URL instantly. 🎉

Option B — Connect a Git repo

  1. Push your folder to GitHub.
  2. In Netlify: Add new site → Import from Git.
  3. Select the repo. No build command needed (static HTML).
  4. Publish directory: / (root).
  5. Click Deploy.
