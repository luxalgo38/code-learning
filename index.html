🎯 Overview 01

lib/database.js is the foundation of the bot's database layer. It creates a single, reusable Sequelize connection — SQLite locally, Postgres in production.

💡 සිංහලෙන් කියනවා නම්: මේ ගොනුව තමයි bot එකේ "database manager" එක. මේකෙන් database connection එකක් හදලා, ඒක එකම එක විදියට තියාගෙන, අනිත් code files වලට ඒක දෙනවා. Local එකේදී SQLite file එකක්, production එකේදී Postgres cloud database එකක් — දෙකම handle කරනවා. 🚀

📄 lib/database.js 
const Sequelize = require('sequelize');

class DatabaseManager {
    static instance = null;

    static getInstance() {
        if (!DatabaseManager.instance) {
            const DATABASE_URL = process.env.DATABASE_URL || './database.db';

            DatabaseManager.instance =
                DATABASE_URL === './database.db'
                    ? new Sequelize({
                            dialect: 'sqlite',
                            storage: DATABASE_URL,
                            logging: false,
                      })
                    : new Sequelize(DATABASE_URL, {
                            dialect: 'postgres',
                            ssl: true,
                            protocol: 'postgres',
                            dialectOptions: {
                                native: true,
                                ssl: { require: true, rejectUnauthorized: false },
                            },
                            logging: false,
                      });
        }
        return DatabaseManager.instance;
    }
}

const DATABASE = DatabaseManager.getInstance();

DATABASE.sync()
    .then(() => {
        console.log('Database synchronized successfully.');
    })
    .catch((error) => {
        console.error('Error synchronizing the database:', error);
    });

module.exports = { DATABASE };

① Sequelize Import

const Sequelize = require('sequelize');

මේකෙන් sequelize කියන npm package එක load කරනවා. Sequelize = Node.js ORM එකක්. ඒ කියන්නේ SQL query ලියන්නේ නැතුව, JavaScript වලින්ම database එක handle කරන්න පුළුවන්. උදාහරණයක් විදියට Contact.findAll() කියලා ලියනවා — Sequelize එකෙන් ඒක SELECT * FROM Contacts විදියට translate කරනවා. 🎩

② Singleton Instance Variable

static instance = null;

මේකෙන් අර්ථවත් වෙන්නේ, connection එක තියාගන්න එකම එක variable එකක් හදනවා කියන එකයි. පටන් ගන්නකොට null විදියට තියෙනවා — ඒ කියන්නේ "තාම connection එකක් හදලා නෑ". පළමු වතාවට require කරද්දී මේක පිරෙනවා, දෙවෙනි වතාවට ඒකම ආපහු use කරනවා.

③ Get Instance Method — හදවත ❤️

static getInstance() {
    if (!DatabaseManager.instance) {
        // ... create connection
    }
    return DatabaseManager.instance;
}

මේක තමයි singleton pattern එකේ මූලික අදහස. පළමු වතාවට call කරද්දී instance = null නිසා block එකට ඇතුල් වෙලා connection එකක් හදනවා. දෙවෙනි, තුන්වෙනි වතාවලට call කරද්දී instance එක දැනටමත් තියෙන නිසා ඒකම return කරනවා — අලුත් connection හදන්නේ නෑ.

✅ ඇයි මේක වැදගත්?

🔹 Call 1: null → අලුත් connection create

🔹 Call 2, 3, 4…: ඒකම connection එක return

🔹 ප්‍රතිඵලය: memory leak නෑ, එකම DB handle එක, SQLite lock errors නෑ

④ Environment Variable Check

const DATABASE_URL = process.env.DATABASE_URL || './database.db';

⑤ SQLite Configuration

new Sequelize({
    dialect: 'sqlite',
    storage: DATABASE_URL,
    logging: false,
})

SQLite = file-based database. storage එකේ දෙන path එකේ ./database.db file එක automatically හැදෙනවා. logging: false නිසා console එකේ SQL queries print වෙන්නේ නෑ — console එක clean. 🧹

⑥ Postgres Configuration

new Sequelize(DATABASE_URL, {
    dialect: 'postgres',
    ssl: true,
    protocol: 'postgres',
    dialectOptions: {
        native: true,
        ssl: { require: true, rejectUnauthorized: false },
    },
    logging: false,
})

Postgres = server-based database. ssl: true කියන්නේ encrypted connection එකක්. rejectUnauthorized: false වැදගත් — cloud DB providers (Neon, Supabase, Railway) ගොඩක් self-signed SSL certificates පාවිච්චි කරනවා, ඒවා Node.js default reject කරන නිසා මේක false කරන්න ඕන.

⚠️ rejectUnauthorized: false ගැන

මේක security අඩු කරනවා (MITM attack risk), නමුත් cloud DB සමඟ වැඩ කරන්න අවශ්‍යයි. Production එකට CA certificate එක manually add කරන එක වඩා හොඳයි.

        console.error('Error synchronizing the database:', error);
    });

sync() කියන්නේ tables auto-create කරන එක. Models define කරලා තිබ්බොත්, ඒවාට අදාළ tables හදනවා. .then() = success, .catch() = error එකක් ආවොත්. මේක Promise එකක් නිසා async විදියට run වෙනවා.

🚨 ලොකු ප්‍රශ්නයක් — await නෑ!

sync() කියන එක await කරන්නේ නෑ. ඒ නිසා sync එක ඉවර වෙන්න කලින් queries දාන්න ගියොත් → "Table doesn't exist" error එකක් එනවා.

විසඳුම: ඔයාගේ bot startup එකේදී await DATABASE.sync() කියලා call කරන්න.

⑧ Export

module.exports = { DATABASE };

මේකෙන් DATABASE object එක export කරනවා — අනිත් files වලට require() කරලා use කරන්න පුළුවන්. වැදගත්: { } ඇතුළේ තියෙන නිසා object එකක් විදියට export වෙනවා.

Import කරන්නේ මෙහෙමයි (destructuring):

const { DATABASE } = require('./lib/database');

💡 Usage Examples 08

Real-world patterns you'll use every day.

🎯 ප්‍රායෝගික උදාහරණ: මේවා තමයි දිනපතා භාවිතා කරන pattern. ඔයාගේ bot එකේ contacts, messages, groups save කරන්න මේ code එකම භාවිතා කරන්න පුළුවන්.

1️⃣ Model එකක් define කරන්න

මේකෙන් "Contact" කියලා table එකක් හදනවා. jid = primary key, name = optional field.

const { DATABASE } = require('../lib/database');
const { DataTypes } = require('sequelize');

const Contact = DATABASE.define('Contact', {
    jid:  { type: DataTypes.STRING, primaryKey: true },
    name: { type: DataTypes.STRING, allowNull: true },
});

module.exports = Contact;

2️⃣ Data save / load කරන්න

upsert = insert හෝ update. findOne = එකක් හොයන්න.

// Save
await Contact.upsert({ jid, name });

// Load
const contact = await Contact.findOne({ where: { jid } });
const name = contact ? contact.name : jid.split('@')[0];

3️⃣ Transaction එකක්

දෙකක් එකට success වෙන්න ඕන නම් — එකක් fail වුණොත් දෙකම rollback වෙනවා.

return await DATABASE.transaction(async (t) => {
    await Message.create({ jid: from, ...msg }, { transaction: t });
    await Message.create({ jid: to,   ...msg }, { transaction: t });
});

4️⃣ Startup එකේ sync එක await කරන්න

මේක තමයි recommended විදිය. Bot start වෙන්න කලින් DB ready කරගන්න.

async function startBot() {
    const { DATABASE } = require('./lib/database');
    await DATABASE.sync();
    console.log('DB ready ✅');
    await startWhatsApp();
}

startBot().catch(console.error);

📊 SQLite vs Postgres 09

Which one should you use?

🤔 මොකක්ද තෝරාගන්නේ? Development එකට SQLite හොඳයි — ලේසි, fast, free. Production එකට Postgres හොඳයි — scale කරන්න පුළුවන්, safe, concurrent. පහත table එකේ සම්පූර්ණ comparison එක තියෙනවා.
FeatureSQLitePostgres
Setup✅ ලේසි (file)⚠️ Server ඕන
Speed (small data)✅ Fast✅ Fast
Speed (large data)❌ Slow✅ Fast
Concurrent writes❌ දුර්වල✅ ශක්තිමත්
Backup✅ File copy⚠️ pg_dump
Cost✅ FreeFree tier / paid
හොඳම එකDevelopmentProduction
🎯 මගේ නිර්දේශය

🔸 Development / personal bot → SQLite (setup එක 10 තත්පරයි)

🔸 Production / many users → Postgres (data loss risk අඩු)

🐛 Troubleshooting 10

Common errors and their fixes.

🔧 Error එකක් ආවද? පහත බලන්න — බහුලව එන errors ටික සහ ඒවා fix කරන විදිය. ඔයාගේ error එක මෙතන නැත්නම්, console එකේ message එක copy කරලා search කරන්න.

❌ Please install sqlite3 package manually

හේතුව: sqlite3 install කරලා නෑ. විසඳුම:

npm install sqlite3

❌ Cannot find module 'pg'

හේතුව: Postgres driver install කරලා නෑ. විසඳුම:

npm install pg pg-hstore

❌ Table doesn't exist

හේතුව: sync() await කරලා නෑ — queries යන්නේ table හැදෙන්න කලින්.

විසඳුම:

await DATABASE.sync();
// then run your queries

❌ SQLITE_BUSY: database is locked

හේතුව: Multiple connections හෝ concurrent writes. Singleton pattern (මේ file එකේ තියෙනවා) use කරන්න හෝ Postgres වලට migrate කරන්න.

❌ Self signed certificate error

විසඳුම: dialectOptions එකේ ssl: { require: true, rejectUnauthorized: false } තියෙනවද බලන්න.

❓ FAQ 11

සිංහලෙන් නිතර අසන ප්‍රශ්න.

MySQL පාවිච්චි කරන්න පුළුවන්ද?

ඔව් ✅ — dialect: 'postgres' වෙනුවට 'mysql' දාලා, mysql2 package එක install කරන්න. ඉතුරු code එක එහෙමම වැඩ කරනවා.

ඇයි singleton pattern පාවිච්චි කරන්නේ?

Singleton නැත්නම්, හැම require() එකකින්ම අලුත් connection එකක් හැදෙනවා. ඔයාගේ project එකේ files 10ක් මේක import කරනවා නම් → connections 10ක් → memory leak + SQLite lock errors. Singleton එකෙන් එකම instance එක guarantee කරනවා.

database.db file එක git එකට commit කරන්න ඕනද?

නෑ ❌. Database එකේ user data තියෙනවා — git එකට යවන්නේ නැතුව .gitignore එකට add කරන්න:

database.db
database.db-journal
.env
node_modules/

Netlify එකේ run කරන්න පුළුවන්ද?

මේ file එක Node.js server එකක run වෙනවා — Netlify static hosting එකේ නෙවෙයි. නමුත් මේ documentation site එක Netlify, Vercel, GitHub Pages, Cloudflare Pages — ඕන එකකට host කරන්න පුළුවන්.
